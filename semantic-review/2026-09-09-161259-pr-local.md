# Cloudflare Pages BFF migration for application email and email OTP

The change moves application-managed notifications, PDF delivery, and email OTP calls behind same-origin Cloudflare Pages Functions and removes the Supabase Edge Function implementations. The Pages layer validates payloads, persists OTPs through Supabase REST with a service-role credential, rate-limits requests, and delegates delivery to `EMAIL_SERVICE`. Caller payloads match the new server contracts, and no active source path still invokes a Supabase email function or mail provider directly. The migration cannot ship as written because the configured service-binding entrypoint does not exist in the bound worker, and essential replacement files are untracked.

Watch for: **confirmed** missing `EmailService` RPC entrypoint; **confirmed** untracked BFF/client/migration files; **confirmed** failed OTP resend invalidating the previous usable code; **confirmed** per-IP-only OTP attempt throttling; **confirmed** absence of integration coverage for these boundaries.

**Verdict**: NEEDS_CHANGES

## High-level view

The browser-facing API is consolidated around `/api/email/notify`, `/api/email/send-otp`, and `/api/email/verify-otp`; the existing PDF and university-contact Pages routes also delegate through `EMAIL_SERVICE`. Payload names and success/error handling align, with no active Supabase Function invocation or direct provider request remaining.

The Pages configuration requests true RPC through the named `EmailService` entrypoint. The checked-out `shared-email-api` worker exposes only a default HTTP `fetch` handler, so the configured binding cannot supply the `sendEmail` method every Pages email route calls.

OTP storage uses server-only Supabase REST credentials and single-consumer deletion. Resend failure removes the prior code before replacement delivery succeeds, while the limiter protects only IP/action pairs and imposes no attempt budget on an email address.

The SQL migration removes the known database-trigger delivery path and revokes direct OTP table access from browser roles. However, the route, browser client, and SQL migration are untracked, so the tracked patch removes the old paths without including their replacements.

## `EMAIL_SERVICE` points at an RPC surface the worker does not export

`wrangler.toml` binds `shared-email-api` with `entrypoint = "EmailService"`, and all three Pages handlers call `env.EMAIL_SERVICE.sendEmail(...)`. Read-only inspection of the clean email-worker repository confirms `src/index.ts` exports only a default object with `fetch`; it has no named `EmailService` export, `WorkerEntrypoint` subclass, or RPC `sendEmail` method. This is **confirmed** and blocks notifications, PDF/contact delivery, and OTP email at binding resolution or method invocation. A compatible RPC entrypoint must exist in the deployed worker, or the Pages layer must use the worker's HTTP service-binding contract, which would not satisfy the stated true-RPC requirement.

The request fields align with the worker's internal `SendEmailRequest`; the failure is the exposed transport surface rather than the payload.

## OTP resend can destroy the last delivered code

`sendOtp` deletes every unverified code for the email before inserting and attempting to deliver the replacement. If `EMAIL_SERVICE` rejects or throws, cleanup deletes the replacement too, leaving no valid code even though the UI reports only that resend failed. This **confirmed** regression should be fixed by retaining the previous record until replacement delivery succeeds, then retiring older records without deleting the newly delivered code; parallel sends must not leave multiple usable codes.

## OTP throttling has no target-email attempt budget

`EMAIL_RATE_LIMITER` is configured at 20 requests per 60 seconds and keyed as `clientIp:action`. Send and verify use separate buckets, and neither key includes the normalized email. This **confirmed** gap leaves a four-digit code exposed to distributed verification attempts and permits distributed OTP-mail flooding of one recipient; the optional binding also fails open when absent. Add an email-scoped send limit and email/code-record verification-attempt budget, retain an IP dimension, and require the production limiter binding.

## Replacement implementation is not part of the tracked patch

`functions/api/email/`, `src/services/emailBff.ts`, and `supabase/migrations/20260909150000_move_email_to_pages_bff.sql` are `??` in `git status`. This is **confirmed** and blocks release: tracked callers import `emailBff`, while tracked Supabase Function deletions and config cleanup remove the old server paths. Add only these intended files before committing and verify the staged diff separately from the repository's unrelated local changes.

## Runtime boundaries have no automated coverage

The migration removes the old OTP diagnostic scripts and adds no tests for BFF action contracts, PostgREST responses, limiter behavior, or service-binding RPC. This **confirmed** gap allowed `wrangler pages functions build` to pass while the target worker lacks the named RPC entrypoint. Add contract tests with a stub RPC service and Supabase REST responses, including failed resend retention, one-time consume, 429 behavior, and declared-entrypoint compatibility.
