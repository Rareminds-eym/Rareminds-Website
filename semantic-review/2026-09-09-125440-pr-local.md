- Confirmed no active source caller uses the retired Render email service, hard-coded production PDF/contact API URLs, or the old `resourceTitle` payload.

## Confirmed findings and qualifications

1. **Deployment — conditional production impact.** The only checked-in GitHub production workflow deploys static `dist` to EC2 and does not deploy `functions/api`. The repository does contain a manual `npm run pages:deploy` path. Production `/api` is broken only if no separately executed Pages deployment or external Cloudflare/Nginx route exists; that infrastructure cannot be verified from this repository.
2. **Payment trust boundary — confirmed in repository code/schema, live impact partly conditional.** The Pages facade forwards a browser-supplied amount without an in-repository authoritative price lookup, and browser code completes registrations through Supabase. The checked-in schema grants `anon` broad access and does not enable RLS for `event_registrations` or `payments`. The external `razorpay-api` worker could perform additional checks, and production Supabase may contain out-of-band policies, but neither is reproducible here.
3. **Mail/OTP abuse controls — confirmed, with existing replay mitigation.** CORS/Origin filtering is not authentication, and no server-side challenge or rate limit was found. OTP codes are four digits and verification has no attempt limit. OTP expiry and the `verified` flag do provide basic replay mitigation, so saying there are no replay controls would be inaccurate; atomic consumption and abuse throttling are still missing.
4. **Blueprint resource — confirmed.** `/institutions/pdfs/Blueprint.pdf` is actively requested but absent from `public/institutions/pdfs`, so `/api/send-pdf` intentionally rejects it. Persistence occurs first, so retries can also duplicate saved requests.
5. **Secret provisioning — environment-dependent.** Runtime code expects `RM_Emails`, but no checked-in Cloudflare or Supabase deployment configuration provisions it. It may already exist in provider dashboards; the repository cannot prove either presence or absence.
6. **Quality/performance debt — confirmed snapshot.** TypeScript debt, 395 lint warnings, 19 development-only advisories, and several 500 kB+ production chunks remain.
7. No automated tests were added, per the audit constraint; validation used build, lint, type diagnostics, dependency audits, and Cloudflare compilation.

## False-positive corrections

- “The repository has no Cloudflare Functions deployment path” is false: `npm run pages:deploy` exists. Only the checked-in EC2 workflow is static-only.
- “All contact email flows were migrated” is false: only the targeted university contact flow moved; corporate/general forms still use their existing Supabase Functions.
- “OTP has no replay protection” is false: expiry plus the `verified` flag provide basic single-use protection, although brute-force, concurrency, and rate-limit risks remain.
- “`RM_Emails` is definitely absent in production” is unproven: it is absent from reproducible repository provisioning but may be configured out of band.
